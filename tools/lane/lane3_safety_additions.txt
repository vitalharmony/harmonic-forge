# Lane 3 safety additions — the closed list (harmonic-forge#322, required change 9)
#
# AC8 says "existing Claude and Codex invocations behave identically."  AC4 says
# Lane 3 safety flags must be un-removable.  Taken literally the two contradict:
# making a Lane 3 safety flag un-removable is only meaningful once such a flag
# exists, and adding one is by definition not "identical."
#
# Lane 1's Plan-First verdict (2026-08-28) resolved that as "identical except
# for deliberately-specified, enumerated Lane 3 safety additions" — and required
# the enumeration to be a committed closed list rather than a soft reading, so a
# future addition FAILS the AC8 check until someone deliberately amends this file
# in its own issue.
#
# Format: one launch-argument token per line, blank lines and #-comments ignored.
# A token listed here is permitted to appear in a Lane 3 launch tuple that is
# otherwise identical to `baseline_launch_tuples.json`.  Anything else is an AC8
# regression, whatever its intent.
#
# THE LIST IS DELIBERATELY EMPTY.  Two decisions put it that way:
#
#   * Codex `--sandbox read-only` — DROPPED from #322 (Lane 1 decision 1).
#     Verified live against codex-cli 0.150.1: at least five further passthrough
#     paths defeat or escalate past it (`-s danger-full-access`, `-c
#     sandbox_mode=...`, `-p/--profile <name>` loading arbitrary on-disk config,
#     `--add-dir`, `--approve-for-me`), and the CLI's flag surface moved twice in
#     one week.  A denylist against that surface cannot hold the property AC4
#     asserts, so AC4 is recorded as VACUOUS-FOR-CODEX rather than shipping a
#     false "un-removable" claim.  Real enforcement is deferred to
#     `.codex/hooks.json` + a `gate_codex_tool.py`-style dispatcher, which is
#     what ADR-007 § 8 already names as the remediation path for this gap.
#
#   * Claude Lane 3 — no new flag (Lane 1 decision 3).  The existing
#     `--permission-mode` passthrough override stays honored at every lane,
#     unchanged.  Tightening Lane 3's Claude posture is real work with its own
#     blast radius and gets its own issue.
#
# AMENDMENT 1 — harmonic-forge#326, 2026-08-28.  The expected first amendment,
# and it landed exactly as #322 predicted: #326 filled the declared-empty
# `AGENT_LANE_POLICY[gemini:3]` slot and changed no launcher code at all.
#
# `--admin-policy` is permitted in a Gemini Lane 3 launch tuple because the
# launcher now supplies it (tools/lane/policies/gemini-lane3.toml).  Supplying
# it is what makes it un-removable: #322 AC4's deny scan derives its list from
# the same `AGENT_LANE_POLICY` declaration, so a passthrough `--admin-policy`
# is now rejected outright at Lane 3, which is the property #326's own AC4
# depends on.
--admin-policy

# AMENDMENT 2 -- hrse#1703, 2026-09-08.  Claude gains `--append-system-prompt`
# at every lane, Lane 3 included (see `_agent_registry.sh`'s
# `AGENT_SYSTEM_PROMPT_FLAG` and `_cli_launch.sh` step 3b).
#
# Different in kind from `--admin-policy` above, worth stating plainly rather
# than silently reusing this file's precedent: `--admin-policy` is a
# PERMISSION boundary (it removes tool access), and its un-removability is
# real -- #322 AC4's deny scan derives from the same registry declaration
# that supplies it, so a passthrough attempt is denied outright.
# `--append-system-prompt` is DIRECTIVE TEXT (a brevity nudge on posted lane
# artifacts, hrse#1703), not a permission boundary, and it is not registry-
# denied the same way: `registry_lane_denied_tokens` covers only
# `AGENT_DEFAULT_FLAG`/`AGENT_LANE_POLICY`-derived tokens, so a caller-
# supplied `--append-system-prompt` in passthrough is not stripped -- it is
# simply a second flag. Verified live (claude 2.1.263): the CLI takes the
# LAST `--append-system-prompt` when given two, so a passthrough one placed
# after this launcher's own would silently win and the directive would not
# reach the session. Accepted rather than closed here: the consequence is a
# missed nudge, not a capability escape, and closing it is out of this
# issue's scope (a real fix would need the launcher to detect and reject a
# passthrough duplicate, which no other AGENT_DEFAULT_FLAG-style entry in
# this registry does today either).
--append-system-prompt

# AMENDMENT 4 -- harmonic-forge#644.  Codex gains `--sandbox workspace-write`
# and `--add-dir <testplan>` at Lane 3 only (see `_agent_registry.sh`'s
# AGENT_LANE_SANDBOX / AGENT_LANE_ADD_DIR and `_cli_launch.sh` step 4b).
#
# Same kind as `--admin-policy` above, not `--append-system-prompt`/`--model`:
# a PERMISSION boundary, and its un-removability is real for `--sandbox` --
# #644's registry declaration feeds `registry_lane_denied_tokens`, so a
# passthrough `--sandbox` is denied outright at Lane 3 (Codex hard-errors on a
# second `--sandbox` token, so "inject unless given" would let a caller
# silently override to `danger-full-access` instead of erroring). `--add-dir`
# is different in kind from `--sandbox` in the same amendment: it is injected
# UNCONDITIONALLY rather than denied, because Codex accepts repeated
# `--add-dir` with no conflict (verified live) -- a caller's own `--add-dir`
# still applies alongside the launcher's. Once this lands, the previously
# memorized manual launch
# `lane3 --agent codex -- resume --last --sandbox workspace-write --add-dir …`
# is refused (its own `--sandbox` is now denied); plain
# `lane3 --agent codex -- resume --last` is the replacement.
--sandbox
--add-dir

# AMENDMENT 3 -- harmonic-forge#665, 2026-09-15.  Claude gains `--model` at
# every lane, Lane 3 included, and `--effort` when LANE_DEFAULT_EFFORT is set
# (see `_agent_registry.sh`'s AGENT_MODEL_FLAG / AGENT_EFFORT_FLAG and
# `_cli_launch.sh` step 3).
#
# Same kind as `--append-system-prompt` above, not `--admin-policy`: a launch
# DEFAULT, not a permission boundary. A passthrough `--model`/`--effort`
# suppresses the injection rather than being denied -- the same #179 override
# affordance `--permission-mode` has always had. The point is that a lane's
# model comes from its launch rather than from whatever ~/.claude/settings.json
# last held, which `/model` and `/effort` rewrite whenever confirmed with Enter.
--model
--effort

# AMENDMENT 5 -- harmonic-forge#754, 2026-09-26.  Codex gains `--no-daemon` at
# every lane, Lane 3 included (see `_agent_registry.sh`'s AGENT_SESSION_FLAGS /
# AGENT_SESSION_DENIED and `_cli_launch.sh` step 4c).
#
# Same kind as `--sandbox` above: an enforcement flag, not directive text.
# Without it, Codex 0.157's interactive TUI hands tool execution to a shared
# app-server daemon started with no LANE, so every LANE-keyed hook -- Lane 3's
# write scoping included -- saw LANE unset (measured live, harmonic-forge#754).
# Its un-removability is real: AGENT_SESSION_DENIED refuses a passthrough
# `--no-daemon` (a duplicate is a hard CLI error) and `--remote` (which would
# route the session to an app server this launcher did not start).
#
# Known gap, recorded rather than silently inherited: this file is only a gate
# while `baseline_launch_tuples.json` is NOT regenerated in the same commit
# that adds a flag -- `test_lane3_launch_flags_match_the_committed_closed_list`
# compares against the committed baseline, so a same-commit regeneration makes
# this amendment unenforced. This amendment was added by hand after a
# preclose-inspection caught the omission (harmonic-forge#754).
--no-daemon

# AMENDMENT 6 -- harmonic-forge#756, 2026-09-25.  Codex gains two `-c`
# sandbox keys at every lane, and two more `--add-dir` grants at Lane 3 (see
# `_agent_registry.sh`'s AGENT_SESSION_FLAGS / AGENT_LANE_ADD_DIR and
# `_cli_launch.sh` steps 4b/4c).  Lanes 1-2 codex baseline cells were
# regenerated for this; Lane 3's were NOT (NC3), so the tokens below are what
# justifies the Lane 3 difference.  `baseline_capture.compare()` accepts only
# ADDED tokens from this list, so a token already in a baseline cell cannot
# silently disappear.  These four are NOT in Lane 3's baseline cells, so
# compare() alone would not notice one going missing (preclose finding);
# `test_lane_launchers.py`'s Codex lane-tmp tests are what require them.
#
# Same kind as `--no-daemon` above: enforcement, and un-removable --
# AGENT_SESSION_DENIED refuses a passthrough `-c`/`--config` override of any
# `sandbox_workspace_write.exclude_*` key or of the whole table (NC4).
#
# The flag that carries a Codex config override.  Reason: the two keys below.
-c
# Reason: stops `workspace-write` from making `/tmp` a writable root, whose
# `.git` protection mount otherwise creates an empty host `/tmp/.git`.
sandbox_workspace_write.exclude_slash_tmp=true
# Reason: the same for `$TMPDIR`, which would re-add `/tmp` via the caller's
# environment and create the same synthetic `.git` there.
sandbox_workspace_write.exclude_tmpdir_env_var=true
# Reason: Lane 3's private TMPDIR root.  With `/tmp` read-only in the sandbox,
# the launcher exports TMPDIR here, and it must be writable for `mktemp`.
<HOME>/.cache/codex-lane-tmp/lane3
# Reason: HRSE2's host-wide launch lock and process-compose log moved to
# `$HOME/.cache/cymagraph/` (hrse PR-A of #756); Lane 3's `gate-restart`
# takes that lock, so the directory must be a writable root.
<HOME>/.cache/cymagraph
