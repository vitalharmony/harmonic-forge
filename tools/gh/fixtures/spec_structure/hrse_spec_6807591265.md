### TC1 — Retry-After recorded (AC1)
A GDELT 429 with `Retry-After: 120` yields one `failures` entry `{"source": "gdelt", "state": "rate_limited", "status": 429, "retry_after": "120", "detail": "HTTP 429"}`. The outcome stays exactly `rate_limited` and `outcome_counts()["gdelt"]` stays `{"rate_limited": 1}`. Class: ac.

### TC2 — Header case and absence (AC1)
The header spelled `retry-after` in a plain dict records the same way. A 429 with no such header records `"retry_after": null` and does NOT raise. Class: ac.

### TC3 — Transport failure and 5xx (AC1)
`FetchFailure(TRANSIENT_ERROR, "ReadTimeout")` records `status: null`, `detail: "ReadTimeout"`. A 503 records `status: 503`. Class: ac.

### TC4 — Rate-limit notice on a 200 (AC1)
A 200 carrying GDELT's plain-text limit notice records `state: rate_limited`, `status: 200`, `detail: "GDELT rate-limit notice"`. Class: ac.

### TC5 — SEC EDGAR (AC1)
A ticker-index 429 and an 8-K 500 each add one entry with `source: "sec_edgar"`. `not_configured`, `ok`, `no_results`, `not_applicable` and `budget_skipped` add NO entry. Class: ac.

### TC6 — Run record and dry run (AC1)
On a test graph from `scripts/graph_fixture.py`, `run_pass` with a stub fetcher returning two failures writes a `SignalFetchRun` whose `json.loads(outcome_counts)["fetch_failures"]` equals those two entries; no entry contains an entity id, URL, query or headline (the `SECRET_HEADLINE` sentinel is absent). The dry-run `render` prints `Failures (n):` with one line per distinct failure and its count, nulls as `-`; `test_h1948_news_signals.py` passes unchanged. Class: ac.

### TC7 — Live, real GDELT responses (AC1)
`pytest -m live` on the live test: every non-`ok`/`no_results` GDELT outcome has exactly one `failures` entry carrying an integer `status` or a `detail` that names a `requests` exception type. When no call failed, the test skips ("no failure occurred to record"); a skip is reported as such, NOT as a pass. The test does NOT assert a success rate (AC2). Class: live.
